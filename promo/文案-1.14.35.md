## 一、正文版（小红书 / 公众号，约 1300 字）

**七版连在一起，这一轮只干一件事：让它能读的书，真的变多。**

七天，七个版本（1.14.29 → 1.14.35）。听起来很勤快，其实大半时间耗在同一个 bug 上，而且我第一遍还修错了。

先说好消息。

### 现在能读什么

以前是 TXT、EPUB、PDF 三样。这回补到七样：

| 格式 | 情况 |
|---|---|
| **DOCX** | Word / WPS 存的直接导入，表格里的字按行读，章节按标题自动分 |
| **MOBI / PRC** | Kindle 的老格式，自己解 PalmDOC 压缩，不装 Kindle、不联网 |
| **AZW3 / AZW** | Kindle 的新格式，自己认章节。带 DRM 的会直说「去 DRM 才能读」 |
| **ZIP** | 一包 txt 合集，拖进来解开，一本一本进书架 |

ZIP 这个功能，是这几天最像「人该干的活」的一个。网上下的一整套 txt 资料包，以前得先解压、再挑出能读的、再一本本拖进去；现在整包丢进来就行。细节上做了这些：

- 只认书（TXT / EPUB / PDF / DOCX / MOBI / AZW3），压缩包里夹的图片、说明、Mac 的资源叉（`__MACOSX`）、`Thumbs.db` 自动跳过
- 单本上限 300 MB，一次最多 300 本，防止一个几百本的合集把界面顶死
- **只在内存里解，不往你的文件夹写一个字节**
- GBK 老编码的 txt 也不乱码

还有一类书：**扫描件 PDF**。整页是图、没有文字层的那种——扫描的书、影印本、族谱、发票。现在能导入、能按页看，翻页、目录、进度、书签、自动封面全都照常。只是上面那层字机器不认识，所以**不能朗读、不能划词、不能做笔记**，点朗读会直说「这本是扫描件，只能看，念不了」。这一点主流阅读器也一样。

### 然后说说错在哪

安卓念英文，从 1.14.31 拖到 1.14.35。症状是：念一行、停很久、跳掉一大段、再念一行。

**第一次判断，我错了。**

我把它归到「中文和英文两套模型并发互锁」，于是加了互斥、加了超时、加了各种兜底。1.14.34 发出去，症状一点没变。

**真因第二次才找到：是一个死循环。**

Java 里切分句子的循环，两张表对不上——句末标点表里有半角句点 `.`，跳过标点的表里却没有。读到英文句号时，下标原地不动，`i = j`，转不出去。而这段循环**攥着旁白那把锁**，所以只要有一句英文，后面所有中文都得排队等它。

英文句子句以 `.` 结尾，所以这不是「偶尔卡一下」，是**必然死**。

两张表对齐，再加一句「没匹配上也必须前进」的兜底，这条路通了。

**但通了之后还不够。** 现象变成「能念，但一段一段跳」。又挖出两个前端问题：

1. 英文切句沿用了中文标点表，`. ! ?` 不在里面 → 整段英文被当成一个巨型句子，按字数硬切，**每一刀都落在单词中间**：`This is a senten` / `ce that goes on`。模型遇到半个词就吐静音，连续两次把英文熔断掉，后面全跳过。
2. 前端判断「英文能不能用」，只看 `/health` 里一个字段。而英文模型是**后台加载**的——页面启动那一刻它必然是 false，之后再没刷新过。于是英文块连预取都没做，每句都要播到跟前才现算，等几十秒。

现在的做法：英文按 `. ! ?` 分句、逗号分小句、**按空格累加，绝不劈词**；硬切点也只放在长度的 0.4 倍之后，宁可留长也不切在词里。判据改成「没收到 415 就当可用」，并且这一章含拉丁字母时，开念就把英文模型建起来。英文引擎也按 CPU 核数开 2~4 路（以前钉死单线程是误判，死锁跟线程数无关）。

模拟器实测：**英文句 5.3 秒出音，接着念中文 1.4 秒**，9 个真实英文段落连打 9/9 成功，不再熔断。以前是 40 秒超时。真机数字还要看你的手机，所以我把它标成「值得一试」，不是「已修好」。

### 顺带提升的地方

- **打开软件不再干等十几秒**：以前应用一起来就重建语音会话。现在改成翻开书才建，只在书架停留的人一次都不用等。
- **换声线不再弹窗停读**：引擎还在准备就跳过这一句、只轻提示一次；连续 3 次出不来才算真坏。
- **中文句里夹英文词不再整句丢失**：认识的按词念，不认识的按字母念（C-P-U）。
- **扫描件不再糊一屏水印**：判据从「有没有字」改成「量每页图像占多大」——整页图占多数、每页字数又少，就按扫描件打开。另外抽全书 25% / 50% / 75% / 92% 四页做样本，防「前 12 页全是彩插」误判。

### 最后，一件我不想再动的事

**安装包太大。** 安卓包 128 MB，桌面完整版 150 MB。

构成是死的：187 人语音库 58.6 MB、英文模型 35.7 MB、两套主角模型各 17.8 MB、推理引擎 21.2 MB。

这两天认真试过瘦身：找 16k / 22k 的多人轻量库、裁掉配角、只留男女主，甚至打了精简包。结论是**没有一套能接受**——8k 的真的不能用，22k 的多人库音色反而更差，砍到只留男女主就撑不起「187 个声音里挑一个」这件事。

所以全部回退了，保持现状。这是「人设」和「体积」的取舍，我选了人设。想清楚之后就不改了。

### 关于「接近完成」

功能上确实差不多齐了：读、听、笔记、同步、各种格式。剩下的都是边角：某些字体没 Unicode 映射的 PDF、用 Kindle 私有压缩（HUFF）的 AZW3、RAR / 7Z 还得先解压。

**明天再想想，如果没什么真要动的，就去开下一个软件了。** 一个东西修到「再改就是折腾」的时候，就该停手。

## 二、短版（朋友圈 / 一句话）

现在英文 5.3 秒出音，接着念中文 1.4 秒。以前是 40 秒超时。

安装包 128 MB / 150 MB，试过换轻量语音库，音质都不能接受，就不动了。**明天再想想，没什么要改的就去做下一个。**
